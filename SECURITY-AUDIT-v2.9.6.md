# PresetHub v2.9.6 Security / Completeness Audit

## Verified fixes
- Hardened optional authentication so blocked/deactivated users and stale session versions are not treated as authenticated.
- Hardened signed preset download tickets with session-version checks.
- Sanitized `/api/users/me` output to exclude reset-token, push-subscription and session-version secrets.
- Public creator lists/search/SEO pages now exclude blocked/deactivated accounts.
- Mounted the standalone `/api/search` route for compatibility.
- Fixed share analytics so cookie-authenticated requests carry the CSRF token.
- Replaced the previously missing `/api/share/qr` dependency with a QR image URL generated by QuickChart; failure is gracefully handled by the existing UI.
- Added a non-unique compound index for download lookup performance without risking legacy-data startup failures.
- Removed a duplicate Telegram bot error message.

## Existing security controls retained
- Server-side admin authorization.
- Environment-only admin credentials.
- Helmet/CSP/security headers.
- CSRF protection for cookie-authenticated state changes.
- Rate limiting.
- Upload extension + magic-byte validation.
- MongoDB GridFS-only user media storage.
- Signed, short-lived preset download tickets.
- Password/session invalidation after password change/reset.
- Escaped/sanitized user-controlled UI output.

OWASP guidance emphasizes validating untrusted input, context-aware output encoding, safe session cookies, and authorization checks as separate controls.
